# IAM plugin 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 1.0.0 of the GLPI 12 plugin `iam`: catalogs (positions, person↔position, resources, roles), RBAC matrix, access register (grants), append-only notes, rights and role profiles, visual matrix with nominal panel, quick search, basic help and agent API guide, multi-entity, with the full 1.0–1.3 schema created up front.

**Architecture:** Same skeleton as `/home/daniel/claude/glpi-plugin-erm` (read it for any convention this plan does not fix): `setup.php`/`hook.php`, PSR-4 `GlpiPlugin\Iam\` in `src/`, Twig templates, `front/` controllers, `ajax/` endpoints. Business logic lives in **pure classes** (no GLPI calls) covered by PHPUnit; GLPI classes are thin wrappers. Authorization is enforced server-side in every entry point and in `plugin_iam_addDefaultWhere` for search/API.

**Tech Stack:** PHP 8.2, GLPI 12.0.x API (CommonDBTM, CommonTreeDropdown, CommonDBChild, CommonDBRelation, DBmysqlIterator), Twig, vanilla JS, PHPUnit 11, PHPStan 2 (level 6), PHPCS PSR-12, Semgrep, Python 3 + Babel for locales.

**Spec:** `docs/superpowers/specs/2026-11-22-iam-design.md` (approved 2026-11-22). Executors read both.

## Global Constraints

- Plugin key `iam`; namespace `GlpiPlugin\Iam`; gettext domain `'iam'`; msgids in English; locales `es_AR`, `es_ES` (+ `en_GB` msgid fallback) built by `tools/` copied from ERM with `erm`→`iam`.
- `PLUGIN_IAM_VERSION = '1.0.0'`, `PLUGIN_IAM_MIN_GLPI = '12.0.0'`, `PLUGIN_IAM_MAX_GLPI = '12.99.99'`, PHP min `8.2`. License GPL-3.0-or-later, author `daniellopez6`, homepage `https://github.com/daniellopez6/glpi-plugin-iam`.
- File header block identical to ERM's, with "IAM - Identity & Access Governance plugin for GLPI".
- GLPI 12 rules: `$PLUGIN_HOOKS['csrf_compliant']['iam'] = true`; typed statics (`public static string $rightname`, `public bool $dohistory`); `Plugin::OPTION_AUTOINSTALL_DISABLED`; tables without `is_recursive` use `getEntitiesRestrictCriteria($t, '', '', false)`; `bin/console cache:clear` after template changes.
- Own top-level menu sector `'iam'` named "Access governance (IAM)" (es: "Gobierno de accesos (IAM)").
- Security (spec §13 ter, OWASP ASVS 4.0 L2): no hand-built SQL; no `|raw` in Twig unless content passed through GLPI's sanitizer; every POST/AJAX checks CSRF and rights; every polymorphic `itemtype` validated against a whitelist; immutable fields dropped from input; entity of a child always taken from its parent; no purge of grants/notes; no secrets or personal data in logs.
- Grant/deviation/matrix-cell entity = **entity of the resource** (spec §7, §12 bis).
- Release checklist (ERM): phpcbf → phpcs → phpunit → PHPStan (read the output; the docker chain does not stop on errors) → semgrep → regenerate locales after any string change → push → CI green → only then `gh release create 1.0.0`.
- Never enable GLPI mail notifications on the VM. VM: `vm@<glpi-host>` (lab GLPI), GLPI in `/var/www/html/glpi`, run PHP as `www-data`.

## Review Focus

1. **Person with several positions, one already ended** → expected access is the union of *active* positions only (`date_end` null or ≥ today); the ended one contributes nothing. Pinned in Task 5 and Task 10 tests.
2. **Person in entity B with a grant on a resource of entity A** → a viewer restricted to A sees it; a viewer restricted to B does not. Pinned in Task 9 (pure scope test) and Task 13 (API check).
3. **Inventory item behind a Resource is trashed or purged** → the Resource stays, shows "linked item deleted", no fatal error on matrix, tab or API. Pinned in Task 6.
4. **Owner group membership changes** → visibility follows current membership at request time, not a cached owner list. Pinned in Task 4.
5. **Large matrix (200 positions × 300 roles)** → page renders collapsed to resource level, cells expand per resource, nominal panel loaded on demand; server builds the model in one query per table (no N+1). Pinned in Task 10 (MatrixBuilder perf test) and Task 11 (ajax per-cell).

    ```
    ['rows' => list<{id,name,area}>, 'cols' => list<{resource_id,resource,roles:list<{id,name,level}>}>,
     'cells' => array<"posId:roleId", {expectation:?string, ok:int, expected:int, unexpected:int, forbidden_held:int}>,
     'holders' => array<"posId:roleId", list<{users_id, state:'ok'|'missing'|'unexpected'|'forbidden_held', grants_id:?int}>>]
    ```
    Semantics: a user belongs to row P if they have an **active** assignment to P.
